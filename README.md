# МетодГраф

Прототип системы подбора педагогических приёмов для урока математики (5–11 класс).

Учитель отвечает на короткий опрос — класс, тема, численность, уровень подготовки,
дисциплина — и получает сценарий из трёх приёмов: **начало → середина → конец**,
с обоснованием выбора и визуализацией графа, по которому шёл алгоритм.

Прототип демонстрационный: 37 тем (по 5–6 на класс), 30 приёмов, 24 экспертные связи.

---

## Что внутри

```
index.html            интерфейс
css/style.css         оформление
js/config.js          ключи Supabase (по умолчанию пустые)
js/data.js            база прототипа: темы, приёмы, теги, связи
js/engine.js          движок подбора — граф, скоринг, поиск пути
js/store.js           слой данных: Supabase или локальный файл
js/app.js             интерфейсная логика и отрисовка графа
supabase/schema.sql   схема таблиц и политики доступа
supabase/seed.sql     данные (генерируется из js/data.js)
tools/gen_seed.js     генератор seed.sql
tools/test_engine.js  проверка движка на всех 999 сочетаниях параметров
```

## Как посмотреть локально

Достаточно открыть `index.html` в браузере — сайт работает на локальных данных,
никакой настройки не требуется.

## Публикация на GitHub Pages

1. Создайте репозиторий, например `metodgraf`.
2. Загрузите в него все файлы этой папки (Add file → Upload files → перетащить).
3. Settings → Pages → Source: `Deploy from a branch`, Branch: `main`, папка `/ (root)` → Save.
4. Через минуту сайт будет доступен по адресу `https://<ваш-логин>.github.io/metodgraf/`.

## Подключение Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. SQL Editor → выполните `supabase/schema.sql`, затем `supabase/seed.sql`.
3. Settings → API → скопируйте **Project URL** и ключ **anon public**.
4. Впишите их в `js/config.js`:

```js
window.MG_CONFIG = {
  SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOi...',
  LOG_REQUESTS: true
};
```

После этого темы, приёмы и связи читаются из базы, а каждый запрос учителя
обезличенно записывается в таблицу `lesson_requests`. Ключ `anon public`
предназначен для публикации в открытом коде: доступ ограничен политиками
row level security из `schema.sql` — справочники доступны только на чтение,
лог — только на запись.

Если ключи не заданы или база недоступна, приложение автоматически
переключается на локальные данные, и прототип продолжает работать.

После изменения `js/data.js` пересоберите данные для базы:

```
node tools/gen_seed.js
```

## Модель

**Теги.** Тема помечена тем, чего она требует от ученика: `вычисления`,
`алгоритм`, `формула`, `понятие`, `абстракция`, `геометрия`, `график`,
`доказательство`, `текстовая-задача`, `ошибкоопасная`, `практика`.
Приём помечен тем же словарём.

**Граф.** Приёмы — вершины. Рёбра двух типов: *тематические* возникают
автоматически при пересечении тегов; *сценарные* заданы экспертно и
описывают сочетаемость приёмов (например, две шумные активности подряд
получают отрицательный вес).

**Фильтрация.** Отбрасываются приёмы, не работающие в нужной фазе урока,
не рассчитанные на такую численность или уровень подготовки; для класса с
трудной дисциплиной исключаются приёмы максимальной динамики.

**Профиль динамики.** Дисциплина задаёт базовый уровень: шумный класс — 2,
рабочий — 3, спокойный и пассивный — 4. Профиль урока: `[база, база+1, база−1]`.
Для «бушующего» класса это 2 → 3 → 1, для пассивного 4 → 5 → 3.

**Поиск.** Перебираются все тройки «начало — середина — конец»; тройка
отбрасывается, если приёмы повторяются или соседние не различаются по
динамике хотя бы на единицу. Вес пути:

```
W = Σ (4·F-мера совпадения тегов + 3·близость к целевой динамике
       + 1·посадка по численности − риск)
    + Σ вес сценарных рёбер + премия за контраст динамики
```

Выдаётся путь максимального веса; ближайшие непохожие пути предлагаются
как альтернативы.

## Проверка

```
node tools/test_engine.js
```

Прогоняет все 999 сочетаний «тема × численность × уровень × дисциплина» и
проверяет, что для каждого находится сценарий, приёмы не повторяются,
чередование динамики соблюдено и жёсткие фильтры не нарушены.

## Что дальше

Веса коэффициентов заданы экспертно и не откалиброваны на эмпирических данных.
Естественное продолжение работы — расширение базы приёмов и тем, сбор обратной
связи учителей через `lesson_requests` и калибровка весов по этим данным.
